# 00-规范基线

> 所有 design/ 文档遵循本规范。文件名不带版本号，版本记文档头。

## slug 规范
- 英文短横线小写：`operation-report`、`user-center`、`data-screen`
- 一个需求一个 slug，贯穿所有文档命名与目录

## 文档命名模板

| 文档 | 命名 |
|------|------|
| 产品需求 | `PRD-SPEC-<slug>.md` |
| 概要设计 | `HLD-<slug>-概要设计.md` |
| 详细设计 | `LLD-前端-<slug>.md` |
| 接口规格 | `API-SPEC-<slug>.md`（条件产出）|
| 任务总览 | `<slug>-TASKS-总览.md` |
| 执行序列 | `<slug>-TASKS-执行序列.md` |
| 测试报告 | `<slug>-test-report-<类型>.html` |
| CR 报告 | `code-review-<slug>.html` |
| 上线清单 | `上线Checklist-<slug>.md` |

**落点**：全部在 `design/<slug>/` 目录下（一需求一目录）。

## 元信息头（每份文档首部固定）

```markdown
> 状态：草稿 | 评审中 | 已定版 | 已交付
> 负责人：@xxx    版本：v1.0    需求 slug：<slug>
> 上游：design/<slug>/PRD-SPEC-<slug>.md
> 变更记录：v1.0 <日期> 初始创建
```

## 铁律
- 文件名不带版本号；版本记文档头「变更记录」
- 旧版移入 `design/_archive/`
- 权威版唯一（不搞 v2/v3 并存，对比看 git）
