## 1. 需求背景与目标
- 背景：列表/报表页面需要按"三级分类"缩小查询范围，三级之间存在父子依赖，不能一次性平铺。
- 目标：一个三级筛选框组件，选择上级后**动态加载**下一级选项，查询结果随筛选联动。

## 2. 用户与场景
- 使用角色：运营/管理员
- 核心场景：
  1. 打开页面 → 一级筛选默认加载 → 用户选择一级
  2. 根据一级选择，加载二级列表 → 选择二级
  3. 根据二级选择，加载三级列表 → 选择三级 → 触发查询

## 3. 功能需求（按优先级 P0/P1/P2）

### F1. 三级联动筛选（P0）
- 描述：三个筛选框（一级/二级/三级），逐级联动加载。
- 交互说明：
  - 进入页面加载**一级**选项
  - 选中一级 → 请求**二级**选项（携带一级 id）
  - 选中二级 → 请求**三级**选项（携带二级 id）
  - 变更上级选择 → **清空**所有下级选项与已选值
- 边界条件：
  - 上一级未选择时，下级置灰/不可用
  - 任一接口失败 → 该级显示错误态 + 重试

### F2. 筛选结果触发查询（P0）
- 描述：三级选择完成后触发列表/数据查询（或独立"查询"按钮）。
- 边界条件：
  - 只选到二级（无三级）→ 按二级范围查询
  - 全部未选 → 查询全量

### F3. 回显（P1）
- 描述：编辑/详情场景，进入时带回已有三级值并逐级加载对应选项。
- 边界条件：回显时需依次请求补齐选项链（一级→二级→三级）。

## 4. 非功能需求
- 性能：单级选项接口响应 < 300ms；列表首屏 < 2s
- 兼容性：Chrome/Edge/Safari 主流版本
- 权限：选项数据是否按角色过滤（待确认）

## 5. 数据与埋点
- 数据来源：分级选项接口，**逐级请求（懒加载）✅ 已确认**
- 埋点事件：
  - `filter_change`：{ level, value, parent_value }（记录每级选择）
  - `filter_search`：{ level1, level2, level3 }（记录最终查询条件）

## 6. 验收标准（★ 可自动验证）
- [ ] 选一级 → 二级列表正确加载（携带一级 id）
- [ ] 选二级 → 三级列表正确加载（携带二级 id）
- [ ] 变更一级 → 二、三级被清空
- [ ] 接口失败 → 显示错误态 + 可重试
- [ ] 空选项 → 显示空状态（不白屏）
- [ ] 回显场景 → 三级链路正确补齐
- [ ] 组件复用 ai-kit（search/forms 类资产），不重复造轮子
