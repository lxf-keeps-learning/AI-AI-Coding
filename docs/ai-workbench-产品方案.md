# AI Delivery Workbench 产品方案（MVP）

> 状态：草案 ｜ 版本：v0.1 ｜ 日期：2026-08-20
> 定位：让产品/测试零门槛使用 AICoding 流水线的 Web 界面

## 1. 背景与目标

**背景**：AICoding 已具备完整的 AI 交付流水线（prd-spec-enhancer → 设计文档链 → 编码 → 测试 → 审查），但入口是 CLI / Cursor / OpenCode，**产品、测试等非开发角色无法使用**。

**目标**：一个纯前端 Web 界面（MVP），让产品粘贴模糊需求 → 一键生成规范 PRD-SPEC → 回答问题补全 → 导出/保存文档；测试可基于 Spec 生成测试计划。

**成功指标**：
- 产品从"提需求"到"拿到 PRD-SPEC" ≤ 5 分钟
- 产品无需学习任何工具，只需浏览器
- 生成的 Spec 结构与 design/_templates/PRD-SPEC模板.md 一致

## 2. 用户与场景

| 角色 | 场景 | 操作 |
|------|------|------|
| 产品 | 需求整理 | 粘贴模糊需求 → 生成 Spec → 回答待确认问题 → 导出 md 给研发 |
| 测试 | 测试规划 | 选择一份 Spec → 生成测试用例清单 |
| 研发（可选） | 快速起稿 | 用界面起 PRD 草稿，再到 Cursor 深入 |

## 3. 功能需求

### P0（MVP 必须）
| # | 功能 | 说明 |
|---|------|------|
| F1 | 需求输入 | 多行文本框粘贴模糊需求 |
| F2 | 生成 Spec | 调 LLM（OpenAI 兼容接口，SSE 流式），system prompt 内置 prd-spec-enhancer 机制，流式渲染 Markdown |
| F3 | Spec 编辑 | 预览/编辑模式切换，改动可保存 |
| F4 | 待确认交互 | 提取 `⚠️待确认` 项 → 集中问题清单 → 回答后一键补全 |
| F5 | 文档管理 | localStorage 保存（slug/标题/内容/状态/时间），列表加载/删除/导出 .md |
| F6 | API 配置 | 设置弹窗（baseURL/model/apiKey 存 localStorage），未配置时引导 |

### P1（MVP 后）
| # | 功能 | 说明 |
|---|------|------|
| F7 | 生成测试计划 | 基于 Spec 验收标准 → 测试用例清单（用例ID/前置/步骤/预期） |
| F8 | 历史版本 | 每次生成保留快照可回看 |
| F9 | 模板选择 | 支持 PRD-SPEC / HLD / LLD 多模板生成 |

## 4. 界面设计（三栏）

```
┌─────────┬──────────────────┬──────────────────┐
│ 文档列表 │ 编辑区            │ 操作区            │
│ ├ 需求输入框（F1）          │ ● 生成 Spec (F2)   │
│ ├ cascade-filter 已定版     │ ● 回答待确认 (F4)  │
│ ├ report-v2   草稿          │ ● 生成测试计划(F7) │
│ └ ...                      │ ● 导出 md (F5)     │
│ 状态/时间                  │ 预览/编辑切换       │
└─────────┴──────────────────┴──────────────────┘
右上角：⚙ API 配置（F6）
```

## 5. 技术方案

- **形态**：纯静态前端（原生 JS 或 Vue CDN），无构建、无后端，浏览器直接打开
- **LLM 接入**：OpenAI 兼容 `/v1/chat/completions`，SSE 流式（fetch + ReadableStream），失败降级普通 JSON
- **Markdown 渲染**：marked.js（CDN）
- **存储**：localStorage（MVP 单人本地）；未来升级 IndexedDB / 后端
- **Prompt 机制**（核心）：system prompt 由 prd-spec-enhancer 机制组装
  - checklist 逐项检查（A-G 板块）
  - 来源标注：`≈推断` / `⚠️待确认`
  - 不编造：真实业务信息标待确认
  - 输出骨架：PRD-SPEC模板.md 固定小节
- **API Key 安全**：MVP 存 localStorage（本地单人），README 提示风险；未来改薄后端代理

```json
  "createdAt": 1724120000000,
  "updatedAt": 1724120000000,
  "versions": []  // P1

```

## 7. 验收标准（MVP 完成定义）

- [ ] 浏览器打开 index.html 即可用，无需构建
- [ ] 配置 API 后，粘贴模糊需求 → 生成结构与模板一致的 Spec（含 ⚠️待确认 标注）
- [ ] 待确认问题集中展示、回答后可补全
- [ ] 文档可保存/加载/删除/导出 .md
- [ ] 刷新页面数据不丢
- [ ] 中文界面，无多余依赖

## 8. 演进路线

```
MVP（1-2 天）         → 验证产品/测试是否愿意用
小规模试用（1-2 周）   → 收集反馈，补 F7-F9
完整版（按需）         → 薄后端 + 知识库 + 多人协作 + 权限
```

## 9. 面试话术（30 秒）

"我给流水线做了一个纯前端工作台：产品粘贴模糊需求 → 一键生成规范 PRD-SPEC（内置 checklist 检查、不编造、待确认集中提问）→ 回答后补全 → 导出给研发；测试可一键生成测试计划。MVP 验证价值，再决定平台化投入。"
