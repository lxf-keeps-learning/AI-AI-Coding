# AICoding 实际项目接入指南

## 目标

业务项目接入后，在 Codex 或 Cursor 中直接输入：

```text
生成一个折线图
```

AI 会先检索 AICoding 的相关 Prompt 和 ai-kit 参考实现，再结合当前业务项目生成代码。

## 接入业务项目

### 方式一：作为开发依赖接入（推荐）

在业务项目安装本地 AICoding：

```bash
cd /你的/业务项目
npm install --save-dev /AICoding所在路径/AI-AI-Coding
npx aicoding install --target .
```

业务项目会通过 `node_modules/ai-ai-coding` 使用 Prompt、ai-kit 和检索脚本。团队发布使用时，可以将依赖地址替换为团队 Git 仓库或内部 npm 包地址。

升级 AICoding 依赖后，再执行一次同步：

```bash
npx aicoding install --target .
```

### 方式二：相邻仓库接入

在 AICoding 根目录执行：

```bash
node scripts/aicoding.js install --target /你的/业务项目路径
```

例如两个项目位于同一父目录：

```bash
cd AI-AI-Coding
node scripts/aicoding.js install --target ../ops-platform
```

### 安装器生成的内容

安装器默认只生成三样东西：

```text
业务项目/
├── .aicoding/config.json              ← 指向 AICoding 知识库（相对路径，不复制 Prompt）
├── .agents/skills/aicoding-codegen/   ← 供 Codex 自动发现
└── .cursor/rules/aicoding-codegen.mdc ← 供 Cursor 自动加载
```

- `.aicoding/config.json` 记录 `sourceRoot`（指向 AICoding 知识库的相对路径）、`promptLimit` 与 `assetMode`；
- 安装器不会复制 `prompts/`、`.cursor/rules/` 或 `src/ai-kit/` 到业务项目，AI 通过 `sourceRoot` 从知识库按需读取；
- 安装器只管理上述固定路径，不覆盖业务项目中其他文件。

完成后重新打开 Codex 或 Cursor 会话。

## 使用方式

最简单的用法：

```text
生成一个折线图
```

更完整的用法：

```text
生成“设备在线趋势”折线图：

- 接口：getDeviceOnlineTrend({ startDate, endDate })
- 两条线：在线设备、离线设备
- 支持近 7 天、近 30 天切换
- 需要 loading、空状态和响应式 resize
```

Codex 也可以显式调用：

```text
使用 $aicoding-codegen 生成一个折线图
```

## 实际执行过程

AI 将执行：

1. 读取业务项目的 `.aicoding/config.json`；
2. 使用 AICoding 检索器匹配 `prompts/charts/`；
3. 读取匹配 Prompt 中引用的 `BaseChart`、`useChart` 等资产；
4. 检查业务项目已有图表组件、依赖、API 和目录规范；
5. 在业务项目生成或修改代码；
6. 运行业务项目已有类型检查、测试和构建；
7. 汇报 Prompt、参考资产、修改文件和验证结果。

## 检索调试

可以独立查看关键词会命中哪些 Prompt：

```bash
node scripts/aicoding.js search "生成一个折线图"
node scripts/aicoding.js search "生成用户 CRUD 列表" --json
```

## 当前能力边界

- **安装器只安装 Codegen**：`.aicoding/config.json`、`.agents/skills/aicoding-codegen/`、`.cursor/rules/aicoding-codegen.mdc`。尚未实现 `--with-spec` 一键安装 PRD-SPEC 能力。
- **PRD-SPEC 是仓库内 Skill**：`skills/prd-spec-enhancer/` 当前在 AICoding 仓库内使用（产出 `design/<slug>/PRD-SPEC-<slug>.md`），不能通过安装器安装到业务项目。
- **HLD / LLD / TASKS 是模板驱动**：`design/_templates/` 提供 HLD / LLD / TASKS 模板，由人工或 AI 协作按模板产出，不是三个独立自动化 Skill。
- **业务项目已有公共组件时**：AICoding 的 ai-kit 只是参考实现，AI 会优先复用业务项目资产；只有业务项目明确复制或配置对应 ai-kit，才允许直接 import。

## 重要边界

AICoding 默认是知识库依赖，不是业务运行时依赖。生成的业务代码不会导入 AICoding 的绝对路径。

如果业务项目已经拥有自己的 `BaseChart`、`useChart` 或图表封装，AI 会优先复用业务项目资产；否则参考 AICoding 的实现生成符合当前项目结构的代码。

团队成员必须能访问 `.aicoding/config.json` 指向的 AICoding 路径。团队使用时建议将 AICoding 和业务仓库放在统一的相对目录结构中，例如：

```text
workspace/
├── AI-AI-Coding/
└── ops-platform/
```
