# 业务词典（探测式激活）

作用：Step3 中，扫描输入与已生成内容，命中"业务指向"即激活对应业务元素，并按"取数指令"补齐真实业务信息。命中即将该元素视为"条件必备"。

> 判定方式：语义命中（关键词是提示，非唯一依据；语义相关即可激活）。
> 本文件是**机制模板**：按业务领域维护自己的词典条目。未命中的条目默认休眠。

## 使用方式

1. 新业务领域：在下方追加条目（元素ID / 业务指向关键词 / 需产出 / 取数指令）。
2. 取数指令指向：输入提取 → AICoding 资产 → `⚠️待确认`（交互确认）。不编造。

---

## 示例：通用筛选/查询场景（可作前端需求词典起点）

### LX1 筛选维度
- **业务指向/关键词**：筛选、条件查询、级联、下拉、树选择、范围、关键字
- **需产出**：筛选维度清单、层级关系（父子依赖？）、是否支持多选/不限
- **取数指令**：输入提取；组件形态参考 `src/ai-kit/search/` 与 `.cursor/rules/search/*`

### LX2 数据来源与接口形态
- **业务指向/关键词**：接口、数据源、懒加载、分页、全量/增量、缓存
- **需产出**：接口契约形态（入参/出参）、加载策略（懒加载/全量）、数据量级
- **取数指令**：输入提取；拿不到真实接口 → `⚠️待确认`，不虚构字段

### LX3 查询触发与结果联动
- **业务指向/关键词**：查询按钮、自动查询、联动刷新、重置、结果集
- **需产出**：触发时机（手动/自动）、联动链路（筛选→列表/报表/图表）、清空语义
- **取数指令**：输入提取 + 自身推理（标 ≈推断）

---

> 真实业务字段枚举、接口路径、权限规则一律不得编造：标 `⚠️待确认` 并汇总到文末。
